# Chirpy Social Media API

> A RESTful JSON API for a Twitter-inspired micro-blogging platform, built with Go and PostgreSQL — using only the standard library's `net/http` package, no HTTP framework.

---

## Features

- **User accounts** — Registration, login, and profile updates
- **JWT authentication** — Short-lived access tokens (1h) + long-lived refresh tokens (60d) with database-backed revocation
- **Argon2id password hashing** — Memory-hard, GPU-resistant (winner of the Password Hashing Competition)
- **Chirps** — Create, read, and delete posts up to 140 characters
- **Profanity filter** — Automatic case-insensitive word replacement using whole-word regex
- **Author-only deletion** — Authorization enforced at the handler level
- **Feed filtering & sorting** — `?sort=asc|desc` and `?author_id=<uuid>` query parameters
- **Premium membership** — Chirpy Red status granted via Polka webhook integration
- **Type-safe SQL** — All queries generated by [sqlc](https://sqlc.dev/) from raw SQL files
- **File server metrics** — Admin hit counter with dev-only database reset

## Tech Stack

| Layer | Technology |
|---|---|
| **Language** | Go 1.22+ |
| **HTTP** | `net/http` (standard library ServeMux) |
| **Database** | PostgreSQL 14+ |
| **Query layer** | sqlc (type-safe code generation from SQL) |
| **Auth** | JWT (`golang-jwt/jwt/v5`), Argon2id (`alexedwards/argon2id`) |
| **UUIDs** | `google/uuid` (RFC 4122, database-native PKs) |
| **Config** | `godotenv` |

## Quick Start

```bash
# 1. Create the database
createdb chirpy

# 2. Configure environment
cp .env.example .env   # then fill in your values

# 3. Run migrations
for f in sql/schema/*.sql; do psql -d chirpy -f "$f"; done

# 4. Install dependencies & run
go mod download
go run main.go
```

Server starts at **http://localhost:8080** — verify with:
```bash
curl http://localhost:8080/api/healthz   # → OK
```

## API Overview

| Method | Endpoint | Auth | Description |
|---|---|---|---|
| `GET` | `/api/healthz` | — | Liveness check |
| `POST` | `/api/users` | — | Register new user |
| `POST` | `/api/login` | — | Login, receive JWT + refresh token |
| `PUT` | `/api/users` | JWT | Update email/password |
| `POST` | `/api/refresh` | Refresh token | Get new access token |
| `POST` | `/api/revoke` | Refresh token | Logout (revoke refresh token) |
| `POST` | `/api/chirps` | JWT | Create chirp (max 140 chars) |
| `GET` | `/api/chirps` | — | List chirps (filterable, sortable) |
| `GET` | `/api/chirps/{id}` | — | Get single chirp |
| `DELETE` | `/api/chirps/{id}` | JWT | Delete chirp (author only) |
| `POST` | `/api/polka/webhooks` | API key | Premium upgrade webhook |
| `GET` | `/admin/metrics` | — | Fileserver hit count |
| `POST` | `/admin/reset` | — | Reset DB (dev only) |

## Project Structure

```
ChirpySocialMedia/
├── main.go                        # Server setup and route registration
├── go.mod / go.sum                # Module dependencies
├── sqlc.yaml                      # sqlc code generation config
├── index.html                     # Minimal frontend at /app/
│
├── internal/
│   ├── auth/                      # JWT, Argon2id, token helpers + tests
│   ├── config/                    # Environment variable loading
│   ├── database/                  # sqlc-generated DB code (do not edit)
│   ├── handlers/                  # HTTP handlers by domain (chirps, users, auth, admin, webhooks)
│   └── respond/                   # JSON response helpers
│
└── sql/
    ├── schema/                    # Numbered migration files
    └── queries/                   # SQL queries consumed by sqlc
```

## Running Tests

```bash
go test ./...                    # all packages
go test -v ./internal/auth/...  # auth package, verbose
```

The `internal/auth` package covers:
- `HashPassword` / `ComparePasswordHash` (Argon2id)
- `MakeJWT` / `ValidateJWT`
- `GetBearerToken` (header parsing)
- `MakeRefreshToken` (CSPRNG)
